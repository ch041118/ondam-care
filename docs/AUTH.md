# 회원가입 · 로그인

실제 계정 모드에서는 서버에 가입하고 로그인해야 합니다. 기기 내 체험 모드는 계정/서버 데이터와 분리되어 있습니다.

## 사용 방법

- PC 브라우저: `npm start` 후 `http://localhost:3000/`에서 **회원가입**에서 요양보호사·사회복지사·어르신 유형 선택.
- 성함, 이메일, 비밀번호(12~128자), 희망 지역/요일/시간/서비스를 입력하면 계정과 근무 조건이 함께 저장됩니다.
- 재실행해도 계정은 유지되며, **연결 설정 → 내 계정**에서 로그아웃 또는 비밀번호 변경을 합니다.
- 기존 모바일 체험 사용자는 상단 **실제 계정 로그인**을 누릅니다. PC 미리보기의 서버 주소는 `http://localhost:3000`입니다.
- Expo Go에서는 휴대폰에서 접근 가능한 HTTPS 기관 서버 주소를 입력합니다. Node 서버는 계속 PC 루프백에만 바인딩되므로 PC의 localhost를 휴대폰 주소로 쓸 수 없습니다.
- 네이버 키가 없으면 주소를 확인 대기 상태로 저장합니다. 계정 가입/로그인/근무 조건 수정은 가능하지만 해당 보호사에게 자동 배정하지 않습니다. 네이버 연결 후 근무 설정을 다시 저장하면 주소를 확인합니다.

## 사회복지사 계정

로그인 화면에서 사회복지사로 가입하면 승인 대기로 접수되며, 관리자 승인 후에만 로그인할 수 있습니다. 관리자는 연결 설정 → 내 계정 → 사회복지사 가입 승인에서 신청자의 신원을 확인하고 승인합니다. 승인된 사회복지사는 현재 단일 기관의 전체 돌봄 정보를 조회하고 조율합니다. 승인 시각과 승인한 관리자 ID를 서버에 기록합니다. 승인 기록이 없는 기존 사회복지사도 대기로 전환되며 기존 세션·기기 연결 코드·푸시 권한은 회수됩니다. 운영자가 직접 발급하려면 아래 명령도 사용할 수 있습니다.

1. 최초 서버를 한 번 실행해 데이터 폴더를 생성합니다.
2. 서버를 종료합니다. 실행 중인 서버와 계정 파일을 동시에 수정하면 안 됩니다.
3. 프로젝트 폴더에서 `npm run account:social`을 실행합니다.
4. 이메일/성함/비밀번호를 입력합니다. 비밀번호 입력은 화면에 표시하지 않습니다.
5. 서버를 재실행하고 관리자 계정의 가입 승인 화면에서 승인한 뒤, 발급한 사회복지사 계정으로 로그인합니다.

관리자 역할은 공개 회원가입으로 만들 수 없습니다. 요청에 따라 현재 로컬 저장소에 `admin` 계정을 별도로 생성했으며 재시작 시 비밀번호를 초기화하거나 다른 설치에 자동 생성하지 않습니다. 관리자는 전체 일정·안부·조율 화면을 이용합니다. `CLOVER_DATA_DIR`와 `PORT`를 바꾸었다면 발급 명령에도 같은 환경변수를 적용하세요.

## 어르신 회원가입

회원가입에서 어르신을 선택하고 이메일, 비밀번호, 성함, 거주 주소, 보호자 연락처를 입력합니다. 보호사가 대신 가입할 수 있습니다. 가입과 동시에 본인의 마이크 화면으로 연결되며, 다시 로그인해도 동일한 어르신으로 연결됩니다. 외부에서 넘긴 어르신 ID나 담당 보호사 ID는 채택하지 않습니다. 주소 확인 서비스가 없으면 가입은 가능하지만 자동 배정은 대기합니다.

## 어르신 기기

보호사가 등록한 어르신의 카드에서 **기기 연결 코드 발급**을 누릅니다. 사회복지사도 기관 어르신을 연결할 수 있습니다. 6자리 코드는 10분 동안 한 번 사용할 수 있으며 어르신 기기 로그인 화면의 **어르신 연결 코드 입력**에서 사용합니다. 이후 어르신은 본인 마이크 화면만 사용합니다. 새 기기에 연결하면 기존 어르신 기기 세션은 폐기됩니다. 보호사가 단순히 배정받기만 한 어르신의 연결 코드는 발급할 수 없습니다.

## 저장과 권한

- Node scrypt(`N=131072,r=8,p=1`, 개별 랜덤 salt)로 비밀번호 해시를 저장합니다. 원문 비밀번호는 저장하지 않습니다. [OWASP 기준](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
- 256비트 임의 세션 토큰을 발급하고 서버에는 SHA-256 해시만 저장합니다. 일반 세션은 7일, 어르신 기기는 30일 만료입니다.
- 웹: HttpOnly/SameSite=Strict 쿠키. HTTPS `PUBLIC_ORIGIN` 설정 시 Secure 쿠키. 상태 변경은 JSON과 동일 출처 검사를 적용합니다.
- Expo: 토큰을 [Expo SecureStore](https://docs.expo.dev/versions/latest/sdk/securestore/)에 저장하며 AsyncStorage나 WebView로 반환하지 않습니다. 서버 주소가 일치할 때만 Authorization 헤더에 넣습니다.
- 기존 Capacitor: 세션은 메모리에만 보관하여 앱을 새로 실행하면 다시 로그인합니다. 일반 Preferences에는 비밀번호나 토큰을 저장하지 않습니다.
- 로그아웃은 해당 세션을 서버에서 폐기합니다. 비밀번호 변경은 해당 계정의 모든 세션과 연결 코드를 폐기합니다.
- API는 화면에 전달된 역할 값을 신뢰하지 않습니다. 보호사는 본인 근무 조건과 배정 일정, 담당 범위의 어르신만 접근할 수 있습니다. 일정 직접 조율/안부 정책/확인 완료는 사회복지사 권한입니다.
- 어르신 토큰은 본인 요청/안부 응답/기기 알림 등록으로 범위가 제한됩니다.
- 계정, 비밀번호 해시, 세션 해시, 연결 코드 해시는 `/api/state`에 노출하지 않습니다. 로그인 반복 시도/연결 코드 추측 횟수를 제한합니다.
- 기존 시연 보호사에게 계정이 자동 연결되지 않으며, 계정이 없는 가상 보호사는 실제 서버의 자동 배정 대상이 아닙니다.

## 운영 범위

현재 저장소는 `data/state.json`의 원자적 파일 교체 방식이며 한 서버 프로세스를 전제로 합니다. 파일을 비공개 위치에 보관하고 OS 접근 권한과 백업을 관리해야 합니다. `CLOVER_DATA_DIR`로 위치를 변경할 수 있습니다. 여러 기관 격리/다중 서버 운영용 데이터베이스 구성은 포함하지 않습니다.

이메일은 로그인 아이디입니다. 이메일 소유 확인, 휴대폰 본인 인증, 자격증 심사, 이메일을 통한 비밀번호 찾기는 아직 연결하지 않았습니다. 비밀번호 변경은 로그인한 계정에서 현재 비밀번호를 확인한 뒤 가능합니다. 이 기능들을 구현한 것처럼 안내하거나 임의 비밀번호 초기화를 제공하지 않습니다.

실제 휴대폰 연결에는 HTTPS 배포가 필요합니다. `PUBLIC_ORIGIN`에 정확한 HTTPS 주소를 설정하고 리버스 프록시를 구성하세요. 외부 서버나 터널을 자동 공개하지 않았습니다. 개발자용 Expo Metro 서버는 API 서버와 별개입니다.

## 검증

`npm test`에서 실제 HTTP 서버의 가입/로그인/쿠키/Bearer/역할 위조 차단/세션 재시작 유지/로그아웃을 검증합니다. 비밀번호 해시, 만료, 계정별 데이터 접근, 연결 코드의 일회성, 비밀번호 변경 시 세션 폐기 테스트도 포함합니다.
