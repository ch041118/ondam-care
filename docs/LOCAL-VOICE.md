# 이 컴퓨터의 음성 요청

무료 로컬 음성 인식을 설치했습니다. `Start-Public.cmd`를 직접 실행하면 앱과 함께 음성 인식·AI를 켜고 ngrok 주소를 연결합니다. 실행 창에서 Ctrl+C로 종료합니다. Windows 로그인 시 자동 실행은 등록하지 않았습니다.

- 한국어 음성 인식: faster-whisper 1.2.1 / Whisper small, CPU int8
- 요청 해석: Ollama 0.34.4 / Qwen3 4B, 로컬 GPU, 클라우드 기능 꺼짐
- 앱 전용 프로그램과 모델: `.tooling/` (소스 관리 제외)
- 설정: `.env` (소스 관리 제외). STT_TOKEN은 외부에 공유하지 않습니다.
- 내부 포트: 음성 인식 127.0.0.1:18000, Ollama 127.0.0.1:11435. ngrok는 앱의 3000번만 공개합니다.
- Python 의존성 버전: `scripts/voice-requirements.txt`

음성 인식 서버는 녹음이나 인식 문장을 로그에 남기지 않습니다. 처리 중 임시 업로드 파일이 생길 수 있으며 요청 종료 시 닫아 제거합니다. 접수된 요청의 문장은 기존 처리 이력에 저장됩니다. 휴대폰에서 PC까지의 연결은 기존 ngrok를 거칩니다.

## 어르신 화면

화면 아래 **계정 · 로그아웃**에서 로그아웃하거나 마이크 권한을 확인할 수 있습니다. 권한 확인은 마이크 접근만 잠깐 열었다 닫으며 녹음·전송하지 않습니다. 처음 권한을 허용한 후에는 마이크를 다시 꾹 누르고 말씀하세요.

Safari는 HTTPS 주소로 접속해야 마이크를 사용할 수 있습니다. 같은 Wi-Fi의 HTTP IP 주소는 마이크 시험용으로 적합하지 않습니다.

## 아이폰의 흰 화면

무료 ngrok는 처음 방문한 Safari에 앱 대신 자체 안내 화면(ERR_NGROK_6024)을 보냅니다. **Visit Site**를 누르면 앱으로 연결됩니다. 해당 화면의 외부 스크립트가 로드되지 않으면 흰 화면으로 보일 수 있습니다. Safari에서 이 사이트의 콘텐츠 차단을 해제하고 다시 열어 보세요. 계속되면 Wi-Fi와 셀룰러 연결을 각각 확인합니다.

Expo WebView에는 ngrok 공식 지원 헤더와 앱 전용 User-Agent를 적용했습니다. Safari 주소창 첫 요청에는 앱 코드가 헤더를 붙일 수 없으므로 안내 화면 자체를 웹앱 수정만으로 제거할 수 없습니다.

## 확인 범위

한국어 합성 음성 “내일 오전 아홉 시에 병원에 같이 가 주세요”를 MP4와 WebM으로 인식하고, 미래 날짜·시간과 병원 동행을 추출하는 것을 확인했습니다. 별도 테스트 데이터에서 실제 음성 요청 API 접수와 어르신 로그아웃 후 세션 차단도 확인했습니다. 실제 아이폰의 마이크·권한·네트워크 동작은 기기에서 추가 확인이 필요합니다. 인식 정확도는 발음과 주변 소음에 따라 달라집니다.

네이버 주소 검색 키와 기관의 실제 요양보호사 일정은 별도입니다. 현재 주변에 배정 가능한 보호사가 없으면 요청은 사회복지사의 조율 대상으로 접수됩니다.

설치 참고: [faster-whisper](https://github.com/SYSTRAN/faster-whisper), [Ollama Windows](https://docs.ollama.com/windows), [ngrok 무료 안내 화면](https://ngrok.com/docs/pricing-limits/free-plan-limits#removing-the-interstitial-page).

## Android 카카오톡으로 열었을 때

카카오톡 내부 브라우저에서 마이크 권한창이 반복된다는 기기 보고에 따라, 해당 브라우저가 감지되면 어르신 화면을 Chrome 이동 안내로 대체합니다. 이 화면에서는 마이크 권한을 요청하지 않습니다. Chrome에서 열기를 누르거나, 열리지 않으면 안내된 주소를 복사해 Chrome에 붙여 넣습니다. 로그인 쿠키를 다른 브라우저로 전달하지 않으므로 Chrome에서는 다시 로그인해야 할 수 있습니다. Chrome과 설치 앱의 기존 녹음 기능은 유지됩니다.

## 음성 인식 3회 실패 시 사회복지사 녹음 확인

- 어르신·안부 확인 건별로 인식 실패를 센다. 빈 음성 인식 결과 또는 해석 결과 형식 오류가 연속 3회 발생하면 세 번째 녹음으로 `말씀 확인` 요청을 만든다. 정상 처리되면 초기화하고, 마지막 실패에서 24시간이 지나도 초기화한다.
- 마이크 권한 거부, 인터넷/서버 연결 장애, 업로드 크기·형식 오류는 인식 실패 횟수에 넣지 않는다. 서버가 받지 못한 녹음을 전달했다고 표시하지 않는다.
- 어르신은 재녹음 없이 “말씀을 녹음해 담당 선생님께 전달했어요” 안내를 받는다. 사회복지사 화면의 **확인 필요** 요청과 건수에 표시된다. 외부 문자·메일을 보내는 기능은 아니다.
- 승인된 사회복지사와 관리자는 요청 상세 → **녹음 불러오기** → 재생 → **일정 직접 조율하기**에서 해석한 부탁, 돌봄 종류, 보호사, 시간, 조율 내역을 입력한다. 근무 시간·일정 충돌·지원 서비스·계정 상태를 확인한 뒤 보호사 수락 대기로 넘어간다.
- 녹음은 `CLOVER_DATA_DIR/voice-recordings/`의 비공개 파일로 저장된다. 공개 정적 경로로 제공하지 않으며, 직원 권한을 확인하는 API로만 읽는다. 일반 보호사·어르신은 원본 녹음을 다운로드할 수 없다. 녹음은 서버 재시작 후에도 유지되며 현재 자동 삭제 기한은 없다. 원본은 필요한 기간만 관리해야 한다.
- 재전송은 동일 녹음 요청 번호로 중복 제거한다. 해결 전 같은 어르신·같은 안부 맥락에서 재차 3회 실패해도 기존 확인 요청을 반환해 중복 업무를 만들지 않는다. 이때 이미 첨부된 세 번째 녹음을 유지한다.
- 웹 화면은 새로고침으로 반영된다. Expo 앱의 녹음 재생 API 허용 목록도 바뀌었으므로 기존 설치 빌드에는 앱 업데이트가 필요하다. Expo Go 개발 실행에서는 최신 코드를 다시 불러온다.

검증: `test/voice-fallback.test.mjs`, `test/voice-fallback-http.test.mjs`. 별도 가상 데이터로 실패 누적·초기화·재시작·재전송·동시 요청·권한·녹음 보존·해석 저장·보호사 수락을 확인한다.
